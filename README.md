## jifeng 做了什么

### 1. 修复中继交互过于苛刻的体验

**原有痛点：** 切断中继需要连续按住交互键 2.4 秒。松键、移动出范围或稍微转开视角就会以每秒 160% 的速度损失归一化进度，半条进度约 0.31 秒便会清空。

**现在：**

| 行为 | 改编后的反馈 |
| --- | --- |
| 在交互范围内按住 E / 手柄 Y / 触屏交互键 | 仍需累计 2.4 秒，显示完成百分比及剩余时间 |
| 松键、短暂转身或离开范围 | 先保留进度 650 毫秒 |
| 超出宽容时间仍未继续 | 每秒回退 35 个百分点，最低为零 |
| 在回退前或回退中继续交互 | 从当前进度接着切断，重新获得下一次中断宽容 |
| 中继完成 | 仅触发一次完成事件，原有敌潮和撤离流程继续生效 |

在范围和朝向符合要求时，提示会区分“按住 E”“进度暂存”“进度回退”。离开有效交互范围或转开视角时，提示仍会隐藏；进度宽容在后台继续计时。此项优化不改变交互范围、敌人伤害、敌潮数量或任务目标。死亡重试仍从任务起点重新开始，不跨局保存中继进度。

参数在 `index.html` 中的 `Yi` 配置：`cutSeconds: 2.4`、`interactGrace: .65`、`interactDecay: .35`。新增的 `fengUpdateRelayProgress` 函数保留可读格式，便于继续调校。

## 玩法与操作

雨天港区防御系统失控。寻找并切断三处上行中继，抵御机械飞鸥与机械猎犬，最后到码头撤离。

| 动作 | 键鼠 |
| --- | --- |
| 移动 / 视角 | WASD / 鼠标 |
| 开火 / 瞄准 | 鼠标左键 / 右键 |
| 换弹 / 近战 | R / F |
| 跳跃 / 冲刺 / 蹲伏 | Space / Shift / C 或 Ctrl |
| 切断中继 | 按住 E，允许短暂中断 |
| 暂停 | Esc 或 P |

触屏使用虚拟摇杆与屏幕按钮；标准手柄使用 Y 交互。点击“开始行动”后启用声音和鼠标捕获。

## 本地运行

无需安装依赖或构建。使用支持 **WebGL 2** 的现代浏览器打开 `index.html`，或：

```sh
python3 -m http.server 8080
```

然后访问 http://localhost:8080/ 。低性能设备可在地址末尾加 `?q=low`。

## 验证

需要 Node.js 运行交互逻辑测试：

```sh
node --test tests/relay-progress.test.cjs
```

测试从实际 HTML 提取新增逻辑及中继更新函数，覆盖正常完成、650ms 内中断恢复、跨越宽容阈值的帧、不同帧步长、回退下限、完成事件不重复，以及游戏提示状态和进度事件的接入。

GitHub Pages 从 `main` 分支根目录发布，提交后自动更新。浏览器画面验证与完整通关是不同的验证范围；本次不声称已完成跨设备性能测试或完整通关。
