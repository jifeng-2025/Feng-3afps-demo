# 盐线行动 · jifeng 改编

**jifeng｜玩法体验设计 · 交互规则调校 · AI 辅助实现与验证**

我围绕浏览器 FPS 中的一个具体问题做了体验迭代：**玩家在切断中继时，需要转身观察敌情，但短暂松键就会迅速丢失进度。** 我的工作是把这个问题拆成可调校的交互规则，完成逻辑与反馈实现，并交付可在线试玩的版本。

## 一个痛点如何变成一次迭代

### 问题：观察敌情的操作，也会惩罚任务进度

原有规则下，切断中继需要按住交互键 2.4 秒。松键、移出范围或转开视角后，进度以每秒 160 个百分点回退，半条进度约 0.31 秒便会清空。

在敌人逼近时，玩家需要判断“继续切断还是转身应敌”。过快清空进度，会把短暂调整与主动放弃任务混在一起。

### 设计：允许短暂调整，保留持续中断的代价

| 场景 | 改编后的规则 | 设计目的 |
| --- | --- | --- |
| 正常交互 | 累计 2.4 秒完成切断 | 保留在危险区域停留的任务投入 |
| 中断不超过 650ms | 保留当前进度 | 容忍短暂松键、观察或位置调整 |
| 中断超过 650ms | 每秒回退 35 个百分点 | 持续放弃交互仍有代价 |
| 恢复交互 | 从剩余进度继续 | 让应敌与任务推进可以衔接 |
| 交互过程中 | 显示百分比、剩余时间和状态 | 让玩家理解进度为什么停留或回退 |

我选择改动交互窗口与反馈，保留任务范围、朝向要求、敌人伤害和敌潮配置，便于聚焦评估这次体验调整。

**当前结果：** 上述规则已实现并可试玩，测试覆盖正常完成、短暂中断、恢复、回退与重复完成边界。尚未开展玩家量化对照测试，因此不将“减少误操作”写成已测得的效果。

## 实现与验证

- 新增 `fengUpdateRelayProgress`，集中处理中断计时、宽容阈值、进度累积及回退。
- 处理跨越 650ms 阈值的帧，只对超出的时间扣除进度，使回退量不随帧步长明显变化。
- 将真实进度接回游戏事件与 HUD，完成后只触发一次任务完成逻辑。
- 保留原有敌潮、任务与撤离流程；死亡重试仍从任务起点重新开始，不跨局存进度。

**调校入口：** `index.html` 中 `Yi` 的 `cutSeconds: 2.4`、`interactGrace: .65`、`interactDecay: .35`。

运行交互逻辑测试（需要 Node.js）：

```sh
node --test tests/relay-progress.test.cjs
```

6 项测试从实际 HTML 提取逻辑，覆盖正常完成、中断恢复、阈值跨帧、不同帧步长、进度上下限，以及 HUD 状态、事件与一次性完成的接入。浏览器检查覆盖启动、进入关卡和项目介绍；不代表完整通关或跨设备性能验证。

## 试玩与本地运行

雨天港区防御系统失控。切断三处上行中继，抵御机械守卫，最后登船撤离。

| 动作 | 操作 |
| --- | --- |
| 移动 / 视角 | WASD / 鼠标 |
| 开火 / 瞄准 | 左键 / 右键 |
| 切断中继 | 按住 E；手柄 Y；触屏交互按钮 |
| 换弹 / 近战 | R / F |
| 跳跃 / 冲刺 / 蹲伏 | Space / Shift / C 或 Ctrl |
| 暂停 | Esc 或 P |

使用支持 WebGL 2 的现代浏览器打开 `index.html`，无需构建。也可运行：

```sh
python3 -m http.server 8080
```

访问 http://localhost:8080/ 。GitHub Pages 从 `main` 分支根目录自动发布。
